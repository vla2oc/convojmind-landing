## Техника

- 2026-09-13 — Анимационная библиотека `motion` (бывший framer-motion) на лендинге разрешена — решение владельца: «можешь скачать библиотеку, чтобы не делать всё через CSS». Причина выбора `motion`, а не `@react-spring/web`: из коробки `whileInView`, stagger, пружины `stiffness/damping`, `pathLength` для прорисовки SVG-линии и `MotionConfig reducedMotion` — у react-spring прорисовку линии пришлось бы писать руками. Цена: возвращаются `'use client'` и вес JS; цифра «до» — 173 КБ gz на страницу, «после» — в `STATE.md`. Запрет из `CLAUDE.md` §2 и `LANDING_PLAN` §2/§9 на этот пакет снят владельцем; в `CLAUDE.md` §2 добавлена оговорка.
- 2026-09-13 — Вход hero (слова h1, подзаголовок, кнопки) — CSS-анимация с пружиной через `linear()`, а не `motion` — потому что h1 это LCP-элемент: у `motion` начальное `opacity: 0` попадает в SSR-разметку и текст появляется только после гидрации, LCP уезжает на время загрузки JS, и критерий готовности «Performance ≥ 90 на мобильном» под угрозой; CSS стартует с первой отрисовки и работает без JS. `linear()` — Baseline с декабря 2023 `[проверено]`, MDN.
- 2026-09-13 — Reveal при скролле: на сервере всё видимо, прячется только то, что ниже сгиба и только после монтирования на клиенте — потому что иначе без JS (или когда чанк не догрузился на плохой связи — диспетчер на стоянке) секции остаются пустыми, а контент выше сгиба мигал бы при гидрации. `animation-timeline: view()` отвергнут: привязан к скроллу, а не ко времени — пружины в нём не бывает; Safari с 26, Firefox с 158, 87 % `[проверено]`, caniuse.
